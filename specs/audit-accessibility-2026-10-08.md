## Concrete defects and remediation

| Source defect | Resulting candidate behavior | Evidence boundary |
| --- | --- | --- |
| Shared `openModal.rerender()` destroyed the focused control without restoring it. Calendar date/month and disruption category/step actions relied on this helper; Tab containment did not recover outside focus. | Renders restore a matching stable control, or focus the dialog panel when the previous action disappears. Only the top dialog contains Tab/focus; hidden, disabled and negative-tabindex controls are excluded from normal traversal. Nested Escape closes only the active dialog. | Actual shared-module keyboard probes and actual disruption dialog pass. Baseline probes independently lose the selected control, initially focus body and close both nested dialogs on one Escape. Booking conflict alternatives already explicitly restored focus and were not misreported as losing focus. |
| Shared modal construction installed listeners before content could throw and registered cleanup too late; an `onOpen` exception could leave an overlay/scroll lock. | Cleanup is registered before rendering; thrown content/opening invokes close and removes focus/keyboard listeners, overlay and scroll lock before rethrowing. | Thrown-content/opening and next-dialog keyboard probe passes; baseline leaves one dialog and body overflow hidden. |
| The separate console payment-proof viewer used `aria-modal=true` but had no Tab/Shift+Tab containment. | Viewer shares the top-dialog focus controller and leaves nested approval/rejection keyboard handling to the active dialog. Close restores the invoking control. | Actual viewer forward/backward wrap, close/return and nested decision scenarios pass in both consoles. Their combined baseline viewer checks fail first on the independently verified focus contrast; absence of original Tab containment is independently confirmed in source, not separately claimed as the first assertion failure. |
| `showFieldErrors` replaced original `aria-describedby`; `clearFieldErrors` removed it, losing registration phone help/password instructions. The disruption reason's inline error had no field association. | Original descriptions remain alongside the error and are restored when errors clear. Disruption reason explicitly identifies its invalid state and associated error. | Actual registration and disruption form probes pass. Registration baseline independently replaces `phone-help` with only its generated error ID. |
| Custom radio and tab roles exposed button behavior without the associated arrow/roving keyboard contract. Tabs lacked panel associations. | Shared-dialog radios (rejection, disruption, booking alternatives) and full-page disruption categories support arrow focus/selection with one tab stop. Player-booking and console-verification tabs use arrow focus, explicit Enter/Space activation, roving tab stops and labelled panel relationships; tab render retains equivalent focused controls. | Actual staff/admin rejection/disruption and three-portal tab scenarios pass, including focus retained through poll refresh. Every corresponding baseline scenario independently leaves focus/selection unchanged on the arrow. These are technical keyboard checks, not screen-reader certification. |
| Mini-chat, verification checklist and revenue paging requested smooth scrolling unconditionally despite reduced-motion CSS. | Those explicit JavaScript actions choose instant scrolling for reduced motion. Existing public carousel already checks the preference. | Independently reviewed source; actual reduced-motion and motion sensitivity acceptance still required. |
| The default blue focus outline on dark viewer surfaces calculated below a 3:1 ratio (approximately 2.96, 2.49 and 2.07 against the source backgrounds). | The viewer uses a 3px volt-coloured outline with spacing against its dark surrounding surface. Other page focus styling remains unchanged. | Actual computed outline/adjacent-surface checks pass in both viewers. Both preserved-stylesheet probes independently fail at a 2.963838 ratio; broader rendered contrast acceptance still required. |
| Console verification `load()` assigned an older category response using mutable current `tab`. Route/session guards do not order two requests within the same active route. | A generation and selected-category check reject superseded success and error responses; counts/list stay associated with the current category. | Both actual-module reversed-response scenarios pass. Both baseline probes independently render the stale Approved record under Rejected after the delayed reply. |

These keyboard contracts follow the primary [W3C APG modal-dialog guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [radio-group guidance](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) and [tab guidance](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/).
