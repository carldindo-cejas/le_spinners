## Defects found and corrected during this review

1. **Active staff/admin conversations failed to open.** `threadPages` used undeclared `threadEl`, before any thread loading. Existing 14 history browser scenarios covered the inbox, not the active thread. Extended tests produced **14 pass / 2 fail**, each with the actual `ReferenceError`; defining the route's thread mount fixes the error. New cases open the thread, fetch Older/Newer, and send a reply in both consoles.
2. **Filters could overlook older actionable records.** Player/console notifications and console inbox search/unread/verifying filters operated on only the current fetched page. Console notifications requested `filter=all` while showing Unresolved, so 125 newer resolved notices could hide older unresolved ones. Filter changes did not reset traversal despite the documented contract. Two isolated API regressions failed before remediation; SQL now filters before LIMIT and scopes cursors by actor/category/search. The UI resets and re-fetches the first page; search is debounced and literal SQL wildcards are escaped. Page-local counts that looked like totals were removed. The tests seed 125 unrelated recent records and three older matches, traverse every match, reject changed-filter cursors and check literal `%_` search.
3. **Changing filters could restore an old-filter cursor after failure.** While an Older request remained pending from page two, a new-filter failed reload reused its rollback state, restoring Page 2 and `old-cursor-1` under the new filter. An actual-module browser regression produced **21 pass / 1 fail** before the fix. Reset/target changes now discard old rollback state; the final suite passes **22 / 22**.
4. **Unsupported SMS was described as future delivery.** The notification page said SMS was queued and would send when configured. It now says Unsupported and states stored SMS is not automatically sent. This agrees with the backend unsupported policy; no provider was added or contacted.

These edits change both frontend and Worker source from deployed version `fd7a20f6-0819-4cf6-8c66-22fb4434d675`. Its earlier live smoke/asset hashes are historical evidence for that deployed candidate, not proof that this reviewed working tree is deployed. Deployment/release gates must identify the new exact candidate and be revalidated through the controlled release process.
