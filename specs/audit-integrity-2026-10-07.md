## Confirmed gaps repaired during review

1. `affectedBookings` used `LIMIT 500` and could accept a whole-resource change after showing only the first 500 affected bookings. It now selects 501 and rejects `TOO_MANY_BOOKINGS` before mutation. The new regression fails on the audited baseline and passes after the fix. Operators must reduce the affected scope before a change; no silent truncation is allowed.
2. The facility edit dialog always submitted original name/status/maintenance defaults, so a rename could undo a later operator’s status or maintenance change. It now submits changed fields only, with dependent maintenance fields for an explicit transition. A separate initial-status option preserves the original baseline when the Maintenance shortcut opens the dialog. Original form behavior failed all six initial browser cases; the repaired seven-case suite passes, including that shortcut.
3. Partial-credit creation’s `credit_applied` event lacked the booking-existence guard. If an occupied slot refused insertion, the event caused a foreign-key error/500 despite rollback. Passing the existing guard restores `SLOT_TAKEN` with no booking, credit debit or effect changes. Reproduced on the preserved pre-auth candidate; current regression passes. This was an additional remediation gap, not a fabricated original-audit result.
